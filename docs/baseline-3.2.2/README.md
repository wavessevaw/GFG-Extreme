`python tools/compare_sandbox.py baseline.json stable.json candidate.json --output comparison.json` checks names and outcomes across three saved runs and reports changed, missing and added finite numeric model values. Lists and nonnumeric values are not compared. The report records the SHA-256 of the exact bytes of each input. Optional --baseline-revision, --stable-revision and --candidate-revision values are caller-supplied claims, not verified source provenance. It exits 1 on a missing scenario/check or any failed check; an otherwise clean comparison remains UNVERIFIED. Identical labels do not prove the same predicate or thresholds. A quantitative comparison requires a separately specified method and measurements; this script does not compare performance or images. CI compares the recorded baseline to its current run and uses that same run as the third input; it does not claim an independent latest-stable comparison.

`sandbox-run.py.txt` is the byte-exact `sandbox/run.py` Git blob from `92b557f678d118ae97948673c26e2498b7a28467` (SHA-256 `3d74ff5a65381ebcb9ff42a32dd9938481e3044e9836828c46290ee2ad0e5764`). `python tools/guard_sandbox_source.py docs/baseline-3.2.2/sandbox-run.py.txt sandbox/run.py` verifies this hash and compares the parsed Python syntax of all 39 original scenario functions and selected shared helpers. Missing or changed definitions return BLOCKED, including changed setup or docstrings; formatting and comments alone are ignored. New scenarios are allowed. This conservative review gate does not say that every change is harmful and cannot detect changes in untracked dependencies, dynamic overrides, or altered tests outside this module. An unchanged result remains UNVERIFIED. Preserve this historical source and explain any approved change rather than altering the reference to suppress a failure.

From a repository checkout, `python docs/baseline-3.2.2/repro_setcap_failure.py` injects a `setcap` failure using the installer's existing fake system and a temporary directory. It reports whether the old runtime survived, without touching the host installation. On 3.2.2 and main `94739b1` it reports `false`. This reproducer reports the observation; a future fix must add an asserting regression test and verify all upgrade and recovery paths.

For an exploratory single-frame comparison, run `python tools/compare_gsf_sdr_frame.py ARCHIVE CANDIDATE.ppm --mode x3 --scene pan --phase 333`. The script verifies the full reference archive, records the truth, baseline and candidate SHA-256 values, and reports RGB code-value PSNR and mean SSIM on non-overlapping 8×8 BT.601 luma windows with population variance, K1=0.01, K2=0.03 and L=255. This is an explicitly defined SSIM variant, not the Gaussian-window reference implementation from [Wang et al.](https://ece.uwaterloo.ca/~z70wang/publications/ssim.pdf); values are not interchangeable. Identical frames have infinite PSNR, represented by `psnr_db: null` and `psnr_infinite: true`. The implementation has analytical tests and a local independent NumPy formula check, but its suitability as a perceptual or release metric is not validated. It does not verify candidate provenance or scene alignment and intentionally reports UNVERIFIED: no acceptance threshold, noise estimate or improvement claim is supplied. A release comparison still requires a predeclared full matrix, repeated measurements, tolerances, temporal and HDR assessment and device testing.
