# Steam Deck comparative test protocol: 3.2.2 and later

Status: **UNVERIFIED** until actual device evidence has been recorded. This extends `DECK_TEST_PROTOCOL_3_0.md`; its ten checks remain historical starting points, not proof of 3.2.2 or current hardware behavior. In particular, 3.2.2 Dash does not expose that document's Custom selector: do not claim a fixed-mode UI test was performed when it was not available. Do not change the original report or historical baseline to make a candidate pass.

## Before a run

Record exact GFG source SHA, archive SHA256, GSF SHA, Gamescope SHA, SteamOS, Decky and firmware versions, display type and actual refresh/HDR state. Record installation provenance and enabled profiles, game build/scene, resolution, graphics and filter settings, power supply, initial battery, fan/ambient conditions, CPU/GPU/TDP limits, HUD, other plugins and relevant background services. Preserve raw data and clock sources. Verify a recoverable stock Gamescope path and the existing watchdog before testing installation. Do not modify system image, kernel, or security mechanisms.

For every experiment, write a plan **before** running the candidate: endpoints, scenes, warmup, measurement duration and sampling rate, number of independent paired repetitions, ordering, exclusion rules, instrumentation, uncertainty calculation, and acceptance thresholds. Compare 3.2.2, the last accepted stable revision and candidate in matched conditions. Use randomized or alternating order, repeat sessions and retain all raw trials including failures. Specify how measurement uncertainty is estimated from independent baseline runs and how a change beyond it is judged; do not set or relax thresholds after seeing candidate data. If the metric, sample size, comparator, instrument or tolerance is missing, mark it UNVERIFIED. Values inside noise are not a proven improvement.

## Required device matrix

Cover OLED 90 Hz; LCD 60 Hz and supported nonstandard rates; dock/external display; battery and charger; SDR and supported HDR; FG Off and Auto and the supported x2/x3 paths, with x3.75 only when explicitly enabled. Exercise Autopilot, Battery, Balanced and Quality, variable game loads, HUD and filters, game start/exit, suspend/resume, engine disappearance/restart, install/update from 3.2.2, uninstall and reboot. Record unsupported and untested combinations individually rather than silently omitting them. Test fixed/custom controls only on versions actually exposing them and record the precise route used.

## Evidence and checks

1. **Installation and recovery:** capture Setup diagnostics and versions before and after install, update and reboot; inspect watchdog/rollback outcomes for a controlled failed boot in a prepared, recoverable environment. Verify stock Gamescope after removal, and restoration of previously captured TDP, CPU/GPU limits and runtime system settings. A unit-test mock does not establish device recovery.
2. **Frame pacing:** save Pace capture and raw presentation timestamps; calculate Real FPS, Output FPS, effective multiplier, frame intervals, P50/P95/P99 presentation error, missed deadlines, repeated frames and recovery after a deliberately recorded hitch. Specify reference timestamps and exclusions. The historical protocol's P95 ≤1 ms, P99 ≤2 ms and missed <0.5% are legacy absolute checks, not substitutes for a predeclared matched comparative method or universally validated limits.
3. **Latency and GPU cost:** retain GPU analysis/reconstruction times and presentation waits separately. Measure input-to-display only with a calibrated end-to-end setup, documented accuracy and synchronized capture. Compute time alone is not input latency. Record renderer, HUD, backend and service overhead separately.
4. **Image quality:** use a fixed, versioned, checksummed, rights-cleared source set and reference output with recorded colour space and HDR metadata. Include fast turns, thin lines, occlusion/disocclusion, frame edges, subpixel motion, scene cuts, HUD motion and recovery after delays. Retain raw frames and alignment; report PSNR/SSIM where applicable plus temporal flicker, edges and localized distortions. Use HDR-aware methodology for HDR. No asset set or validated metric implementation is asserted by this protocol.
5. **Power and control:** sample APU draw, TDP, temperatures, clocks, CPU/GPU utilization and Real FPS with timestamped provenance. Compare energy over identical sessions along with pacing and image quality; save controller events and user limits. Verify controller ownership, handoff on external control, no changes based on stale telemetry, and restoration after exit and suspend/resume.
6. **UI and observation:** record all four tabs at Decky width, all HUD positions/details and filter presets. In 3.2.2, a second tap of the selected mode turns FG off, no mode is highlighted while off, and choosing a mode returns FG. Check engine confirmation and visible state, not just a successful RPC.

## Record and decision

Store per-run manifest, input assets and hashes, raw telemetry and timestamps, Pace captures, screenshots/video where permitted, logs, device settings, calculated metrics, exclusions and failures. Include the predeclared plan and the exact analysis software revision. Label evidence **functional**, **simulation**, or **hardware**; do not combine them into a single pass. Report each matrix cell as PASS, BLOCKED or UNVERIFIED with reasons. A critical graphics change without required device evidence cannot be Stable. Collect one consolidated candidate for device qualification after software checks; do not request repeated intermediate tests of unfinished fixes.
