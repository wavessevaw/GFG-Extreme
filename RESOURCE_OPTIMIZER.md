# Resource Manager

Install the GFG Extreme 3.5.0 Decky ZIP from the release page, then open Engine during a game. The existing Resource Optimizer switch controls all policies. Reinstall GFG Extreme 3.4.4 to roll back.

The session manager samples system PSI and the eligible Baloo and Syncthing cgroups every five seconds of gameplay. For three successive windows, CPU PSI of 5% or more, a service using at least 0.25 core and late native frame intervals can trigger a 30-second CPU-weight trial. Only the desktop user's verified executable set in the expected leaf cgroup qualifies. With sustained Baloo indexing above half a core, GFG can instead limit indexing to 25 ms per 100 ms. This bandwidth trial also works during smooth, low-pressure gameplay on a confirmed discharging battery. Loss of that power condition releases a headroom-only trial. A two-minute cooldown limits repeated trials. The desktop user manager independently restores the journalled value on helper exit. Existing limits, replacement cgroups and external overrides receive protection.

The Engine panel reports up to four active service or scope subtrees. It reads cgroup CPU time and per-device io.stat at 25-second intervals under low pressure and 10 seconds under CPU or disk pressure. Each of the app, background, session and system slices has a 64-directory discovery budget. Nested slices are traversed, and a reported unit includes its descendants exactly once. CPU is percent of one logical CPU. Disk read/write rates are MiB/s on the busiest observed major:minor block device for that unit. Device stacking, missing controllers, buffered writes and the bounded scan limit attribution. The panel labels matching active Steam app scopes, known session infrastructure, system units and verified background service paths. Unrecognized layouts remain unclassified. These labels are diagnostic. Only the separate verified control paths can change resource limits.

During gameplay, systems with the native restic or Borg binary check the desktop user's timers at most once a minute on a worker. GFG checks for a matching restic-backup.timer or borg-backup.timer about to fire within 90 seconds. It verifies its inactive oneshot service, timer relationship, dependency checks, absence of startup hooks, and the actual executable and backup/create argument. Custom wrappers, restore/check commands and already running jobs do not qualify. For eligible jobs GFG requests a transient systemd ordering dependency. The timer stays enabled and the manager owns the queued start. The window releases on game exit, disable, benchmark, backend pipe closure or the independent 15-minute timeout. A manual start of the very same backup unit during the window is also subject to that ordering. A missed probe leaves normal scheduling in effect. The manager skips this work entirely when neither supported binary exists. This mechanism requires a working user bus, systemd-run pipe support and user unit ordering. It does not require changing backup profiles or timer files.

## Validation

Backend tests cover CPU-headroom decisions, quota rollback, device counters and nested scopes. The Linux CI integration creates a disposable scheduled oneshot and checks that a real user manager queues a timer firing and executes it when the pipe closes. It also rejects a mismatched command. The fixture writes a marker. Actual Borg and restic repositories are outside the integration test.

On Steam Deck, compare the same scene in alternating enabled and disabled runs on battery with fixed TDP, display and game settings. Record native frame P95/P99, APU draw, battery discharge and the actual scheduled job completion after exit. Inspect cpu.max after plugging in or stopping GFG. Check real backup logs before and after a session. Hardware FPS, battery and thermal effects are unverified.
