# Resource Optimizer test candidate

Based on GFG Extreme 3.4.4. Install the full ZIP in Decky. The original bundled Gamescope runtime is unchanged. Open Engine and check Resource Optimizer during a game. Reinstall the 3.4.4 ZIP to roll back.

During gameplay, the backend samples CPU, memory and I/O PSI every five seconds. It checks the desktop user's KDE Baloo service in background.slice and Syncthing's user service in app.slice or background.slice. The check requires a leaf cgroup, the expected user, recognized executable paths for every member and a default CPU weight of 100. Custom layouts, wrappers and mixed services stay under observation. The backend reads individual candidate cgroups without enumerating all system processes.

For relative CPU-weight trials, three successive windows for the same cgroup must show at least 0.25 core of service CPU activity, system CPU pressure of at least 5% and late native frame intervals. When both services qualify, the busiest gets the single trial. The Engine panel reports the selected service once its weight is confirmed. Loss of eligibility or a greater than 25% worsening of P95 against the pre-trial window ends the trial early. These observations establish coincident contention, not the cause of a particular missed frame.

The desktop user manager runs a bounded 30-second trial at CPU weight 50. A private user-runtime receipt records the original default weight, boot ID and group inode. ExecStopPost restores the value after termination independently of Decky. The helper refuses nondefault weights and preserves external changes. A failed restoration leaves the receipt for the next trial. Reboot recreates runtime cgroups. A two-minute cooldown separates trials. CPU weight affects relative service among contending siblings and may have little effect across slices.

Memory and I/O pressure are observational. GPU activity attribution, per-device storage latency and swap/reclaim attribution are unverified. The package has no hardware FPS or power claim. To measure on LCD and OLED, repeat the same scene in alternating enabled/disabled runs at fixed display, TDP, FG and game settings. Compare native frame intervals, 1% lows, P95/P99, pacing, PSI and APU draw. Confirm original weight after exit, disable and a Decky crash. A manager that cannot delegate cpu.weight leaves the trial ineffective.

The panel distinguishes system-wide CPU wait (PSI some avg10) from the CPU time used by individual user services (100% equals one logical CPU). It reports up to three services using at least 1% from a bounded sample of the first 64 entries in each of app.slice and background.slice. The figures describe the last measured gameplay interval. A displayed service can be part of the game environment. Displaying it never authorizes a control operation.

An isolated Baloo indexer consuming at least half a core with CPU PSI at or above 5% for three consecutive five-second windows can now receive a bounded CPU bandwidth trial even with smooth frames. For 30 seconds it can use 25 ms CPU time per 100 ms period. This path requires default weight and the original unlimited quota with a 100 ms period. The independent cleanup restores the quota unless a different manager changed it. Syncthing remains eligible only for relative-weight trials. CPU quota may defer indexing and shift energy use to after gameplay. Steam Deck power and temperature effects require measurement.
